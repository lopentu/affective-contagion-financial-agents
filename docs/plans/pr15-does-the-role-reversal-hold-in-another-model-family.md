# PR15 · Does the role reversal hold when a different family of model does the reading?

- Governs E39. Frozen 2026-08-08, **before any reading existed**.
- Analysis script `e39_analysis.py`, hashed before the run was queued. The hash is recorded in the
  experiment entry.

## The question in one sentence

E36 found that five agents reading the *same* message
respond by different amounts, and one of them responds in the opposite direction. Every reading in it
came from one model. This asks whether a reader from a different company's model does the same thing.

## Why it is worth the GPU time

The paper's central claim is not "traders are suggestible". It is **"averaging over agents can report a
null that is not there, so report per agent"**. That is advice to anyone evaluating a team of language
models, and it only holds if the heterogeneity is a property of agents-reading-messages rather than a
quirk of Qwen3-4B.

*"You have shown prompt-specific lexical behaviour, not a general property of financial roles."* One
model cannot
answer that. Two more can go a long way.

## What is held fixed, and what varies

**Fixed.** The 59 matched stimulus pairs from E36, byte for byte. They were generated by Qwen3-4B and
are reused unchanged, so the message a reader sees is identical to the message E36's readers saw. The
five reader roles, their system prompts, both contexts, three draws, the lexicon, the scrub, and the
aggregation are all E36's.

**Varies.** Only the model doing the reading:

| | Checkpoint | Family | Size |
| --- | --- | --- | --- |
| E36 (already run) | `Qwen/Qwen3-4B-Instruct-2507` | Alibaba | 4.0B |
| **new** | `ibm-granite/granite-4.1-3b` | IBM | 3.4B |
| **new** | `google/gemma-4-E4B-it` | Google | ~4B effective |

Holding the stimulus fixed is deliberate. If we regenerated the stimuli with each family we would be
varying the message and the reader at once, and a difference could be either. This way exactly one
thing changes.

**What that costs, stated now rather than when it is inconvenient:** the message these readers see was
written by a Qwen model. So this tests whether *readers* from other families show the heterogeneity. It
does not test whether other families *produce* messages that carry it. That is a separate run and this
one cannot substitute for it.

## Size, and why these two

Both new checkpoints sit within 0.6B of Qwen3-4B, so a difference is family and not size. That matters
because E37 found the effect declines with size: had we
reached for the 8B Granite, a null would have had two explanations and we could not have separated
them.

Both already pass E12's load check, both are
already downloaded, and both are Apache-2.0.

## The run

59 pairs × 5 reader roles × 2 contexts × 2 arms × 3 draws = **3,540 readings per family**, 7,080 in
total. E36 generated 7,080 in about three hours, so this is roughly three hours.

One replicate, not two. E36 and E37 both ran their design twice and no cell flipped sign where both
passes were clear of zero. Repeatability has been paid for; buying it a third time would cost the
second family.

## What is measured

Reader arousal, NRC VAD v2.1, `surface_then_suffix`, signed scale, after
`scrub_decision_vocabulary` — identical to E36 so the numbers are comparable. Draws are averaged to
the (pair, role, context) cell before anything else; three draws of one stimulus are not three
observations.

## The decision rule, fixed now

**Primary, one per family.** A permutation test on the *spread* of the five role effects: shuffle the
role labels within each pair, recompute the standard deviation across roles, 2,000 times. This is
E36's estimator unchanged. Two families means two tests, so **Holm across the two**.

- **Heterogeneity replicates in a family** if that family's permutation test survives Holm.
- **Heterogeneity replicates, full stop** if both do.

**Secondary, and it is the more interesting question.** Given heterogeneity, is it the *same*
heterogeneity? Two things, both descriptive, neither corrected:

1. Spearman rank correlation of the five role effects against Qwen3-4B's, per family. With five roles
   the smallest attainable two-sided p is 2/120 = 0.0167, and we report the exact permutation value,
   not the large-sample formula. E37 is the reason: the
   asymptotic formula gave 0.014 where the exact value was 0.024.
2. Sign agreement: of the five roles, how many share Qwen's sign *while both are clear of zero*. Cells
   where either interval contains zero are counted separately and never as agreement. This is the rule
   E36 arrived at after a stability check false-alarmed on two near-zero cells.

**Per-role effects** with Holm across five roles within family, reported whatever the primary shows,
but **descriptive only if that family's primary fails**. No role may be singled out from a family whose
heterogeneity test did not survive.

## Run health, reported before any effect

Reported first, as E36 does, because a broken generation makes every number below meaningless.

| Check | Threshold fixed now |
| --- | --- |
| Parse success, per role and context | ≥ 95% |
| Readings written | 3,540 per family, exactly |
| Pairs contributing all five roles | ≥ 50 of 59 |

**A family whose parse rate falls below 95% in any cell is reported as uninterpretable, not as a
negative.** This is not a formality. E11 found
Qwen2.5-3B showing no effect where Qwen3-4B showed a large one, and the honest reading there was that
the smaller model could not do the task rather than that the effect was absent. A model that cannot
produce the output format is in the same position.

## What counts as nothing, and which kind of nothing it is

Three outcomes, and they license different sentences:

**Both families show heterogeneity, orderings agree.** The claim generalises. The paper says "reader
role changes the response in three model families" and the advice to report per agent is grounded.

**Both families show heterogeneity, orderings differ.** This is the outcome I expect to be most
argued about, so the reading is fixed now: **it supports the paper's actual claim and refutes a
stronger one we have never made.** Averaging over agents still destroys a real effect, in every
family. Which agent moves most is model-specific, and the paper must then stop implying that "trader"
names a stable property. That is a better paper than a clean replication would give us, and saying so
afterwards would be retrofitting, which is why it is written here.

**A family shows no heterogeneity.** Two readings, and the run health decides between them. Parse rate
healthy and spread interval excluding E36's 0.0107 → a genuine non-replication in that family, and the
paper's claim narrows to the families where it holds. Parse rate healthy but the interval containing
both zero and 0.0107 → **uninformative for that family**, and it is reported that way rather than as
evidence of absence.

## Sensitivity, computed before the run and not after

E36 measured a spread of 0.0107 across roles on these 59 pairs with three draws. This design has the
same pairs, the same draws and the same estimator, so its precision is E36's precision up to the new
model's own noise. E36's permutation test returned zero of 2,000 draws at or above the observed
spread; a spread half that size would still have sat outside the null's bulk.

What this design **cannot** do: detect a spread much below 0.005, and distinguish a genuinely small
spread from a noisy one in a model whose generation variance is materially larger than Qwen's. If a
family returns a spread under 0.005, the answer is "too small for this design to size", and the
bootstrap interval on the spread is what says so.

## Reporting

E36's `p = 0.0005` is the smallest value 2,000 permutations can
produce, not an estimate of a tail. **Report `p < 0.001`, or the count as `(0+1)/(2000+1)`, and never
a bare 0.0005.** That applies retroactively to E36's number in the paper.

Both new numbers are registered in `docs/verified-numbers.toml` with their estimator and provenance
before they appear in any document.
